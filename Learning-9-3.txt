Regular functions have a dynamic this, while arrow functions have a lexical this(based on what they're inside)
in a regular function this is determined by how the function is called, it defaults to the object executing the function. If a regular function is called on its own, it defaults to the global window object or undefined in strict mode. 

const user = {
  name: 'Alex',
  regularLog: function() {
    console.log(this.name); // 'this' refers to the 'user' object
  }
};

user.regularLog(); // Output: "Alex"

Arrow functions on the other hand don't have their own this binding, instead they inherit this from the surrounding code context (Parent scope) 
const user = {
  name: 'Alex',
  arrowLog: () => {
    console.log(this.name); // 'this' is inherited from the global scope!
  }
};

user.arrowLog(); // Output: undefined (or empty string, because window.name is empty)

They save the day with callbacks, like setTimeout or array methods, where regular functions routinely break. 

const counter = {
  count: 0,
  start: function() {
    // Regular function inside setTimeout
    setTimeout(function() {
      this.count++; // ERROR: 'this' here points to the 'window' object!
      console.log(this.count);
    }, 1000);
  }
};

counter.start(); // Output: NaN (because window.count is undefined)


So in this case this loses track of the counter object. 

const counter = {
  count: 0,
  start: function() {
    // Arrow function captures 'this' from the start() method context
    setTimeout(() => {
      this.count++; 
      console.log(this.count);
    }, 1000);
  }
};

counter.start(); // Output: 1

Function components existed, but couldn't hold state at all. So really anything post 2019 can be seriously outdated. 

So what is Redux? Redux is a library for managing state that components need, it has nothing to do with class vs hooks. The problem it addresses is if state lives in a component, and there are several distant components needing the same data, it has to be lifted to their common ancestor and threaded down through everything between. Super ugly, and the prop drilling we talked about. Redux handles this, moving the data into one store outside the component tree. Components read from it directly and dispatch actions to change it. No drilling. But React added useContext for lighter cases, and most serrvers moved to React Query, and Redux itself got a modern API.
