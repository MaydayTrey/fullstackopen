How does React deal with shallow copies? The new object, changedNote is a shallow copy, the values of the new object are the same as the values of the old object, if the values of the old object were objects themselves, then the copied values in the new object would reference the same objects that were in the old object --- What this sounds like is past the first layer, they'd be pointers to the objects which were supposed to be copied, I feel like that could be a serious issue for React since it requires a new object state, not this pointer referencing? 
Answer: My understanding of shallow copying is right- and a well-known category for React bugs.
React compares the object you hand to the setter against the previous, by identity, one level. So spread produces a new outer object, and by that comparison it appears as a changed object and re-render occurs. This can be useful, in that it lets React skip work on components whose props didn't actually change. But when you mutate through shared reference, you can get some nasty errors.
const updated = { ...person }
updated.address.city = 'Franklin'
setPerson(updated)
---> updated is a new outer object, so React will re-render, but updated.address and person.address are the same object, pointing to a referring to the same thing! The old state gets mutated too, so React notices no difference, because there is no dif!
The fix is spread at every level of change:
const updated = {
  ...person,
  address: { ...person.address, city: 'Franklin' }
}

Every object on the path from the root to the thing you're changing needs to be new!

Later on you'll learn of a library called Immer which allows you to write mutating-looking code and produces correct immutable updates underneath, will be covered later.

Axios handles rejected promises by providing the then method with a second callback function, which is called in the situation in which the promise is rejected. You more commonly, will use the catch method for rejected promises.

axios
  .get('http://example.com/probably_will_fail')
  .then(response => {
    console.log('success!')
  })
  .catch(error => {
    console.log('fail')
  })

When doing multiple .thens, you are creating a promise chain.
The catch method defines a handler function in the event any of the promises within the chain fail, a function will be called to handle the failure.
